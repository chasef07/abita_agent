## Issues Found

1. **Ignored human-transfer request during spelling loop** — SCL_ffWvAhkfphmz, turn 22
   Caller explicitly said "Can I speak to a human?" while agent was deep in a last-name spelling loop. Agent ignored the request and continued spelling. RUNBOOK already had the two-request transfer rule but it didn't explicitly override in-flight tasks.
   Root cause: Rule ambiguous about whether human-request applies mid-data-collection.

2. **Name stuffed into email field** — SCL_c28biLNL3jhd, turn 22
   Agent called `add_patient` with `email: "Spencer Hamelman"` because the caller said the subscriber name when asked for email. The add_patient description said "never fabricate" but did not enforce field-level integrity (right answer → right field, email must look like email).
   Root cause: Tool description gap on cross-field contamination and email format.

3. **Hallucinated DOB before caller provided one** — SCL_TnJbZv2eH77p, turn 2
   Agent called verify_patient with `dob: "01/01/1970"` after caller had only given name + appointment context. The verify_patient description didn't explicitly forbid fabricating parameters (add_patient does).
   Root cause: Tool description gap — no "don't fabricate" rule on verify_patient.

4. **Hallucinated caller names from garbled STT** — SCL_dxVJRKt9QrrB (turn 3, "Jim" from "Whitney—"); SCL_RrpTF3oCabSL (turn 4, "Kenny" from "Any—")
   Agent greeted callers by names it guessed from partial/misheard syllables. Existing "Get the name right" rule said "Trust what you hear" but offered no guidance when the input is a fragment.
   Root cause: RUNBOOK rule incomplete for ambiguous name input.

5. **Repeated identical question 4x** — SCL_c28biLNL3jhd, turns 12-15
   Agent asked "are you male or female?" four consecutive times with identical wording. Existing "break stuck loops" rule already covers this — the LLM simply ignored it.
   Root cause: LLM error — rule exists, wasn't followed. Not fixable with more prompt text.

6. **Synthesized email from letter fragments** — SCL_CeCxVCHDDa2o, turn 20
   Agent compiled `tmcre@gmail.com` from the caller saying "8T— M is in Mary, C is in Charlie— R-O-E— @gmail.com" — partial, unclear letters fused into an email guess. Covered by the same add_patient fix (email must be valid format, don't synthesize from fragments).
   Root cause: Same as #2.

## Changes Made

1. **src/tools.ts — `add_patient` description**: Added explicit field-integrity rules. Every field answer goes in its own field (never stuff a name into email). Email must contain "@" and a real domain — if the caller didn't give a clean email, ask again or pass empty string.
   Why: Prevents subscriber names, random fragments, or placeholders from landing in the email field (as in SCL_c28biLNL3jhd).

2. **src/tools.ts — `verify_patient` description**: Added "Every parameter must come from what the caller explicitly said — never fabricate a DOB, last name, or any other value to 'try' the lookup."
   Why: Mirrors the existing add_patient rule for the other patient-data tool. Addresses SCL_TnJbZv2eH77p.

3. **workspace/RUNBOOK.md — Path 4 (Caller asks for a human)**: Added override clause. "This rule overrides any in-flight task." If the caller uses a trigger word during registration, a spelling loop, or any other data collection, STOP that task immediately — do not keep spelling, do not keep asking for fields.
   Why: Addresses SCL_ffWvAhkfphmz where agent ignored "Can I speak to a human?" mid-spelling-loop.

4. **workspace/RUNBOOK.md — General Rules "Get the name right"**: Extended. "Never greet a caller by a name you guessed from a fragment or garbled syllable. If you can't make out the name, ask them to repeat or spell it — don't pick a likely-sounding substitute."
   Why: Addresses SCL_dxVJRKt9QrrB and SCL_RrpTF3oCabSL (Jim/Whitney, Kenny/Any).

5. **src/__tests__/replay.test.ts — Two new tests**:
   - `mid-collection human request`: agent replays a 7-turn spelling-loop history, caller says "Can I speak to a human?", asserts agent does not call `add_patient` and (via LLM judge) the response acknowledges the human request rather than continuing the spelling loop.
   - `email field integrity`: agent replays a 6-turn registration history, caller says a name when asked for email, asserts any `add_patient` call does not put the name in the email field and that email (if present) contains "@".
   Also mirrored the new add_patient field-integrity rule into `mock-tools.ts` so the mock description stays in sync with the real one.
