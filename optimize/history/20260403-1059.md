## Issues Found
1. **Spanish phone number confusion loop** — SCL_SuQdqrt9Ys9g, turns 29-90
   Root cause: Agent didn't understand Spanish compound numbers (diez=10, once=11) as individual digits. Prompt had no guidance for this.

2. **Day-of-week mismatch** — SCL_SuQdqrt9Ys9g, turn 133
   Root cause: Agent offered April 22 (Wednesday) as a Thursday without verifying. No rule required day-of-week validation.

3. **Missed transfer on specific name** — SCL_kfDQPipRtb6F, turn 2
   Root cause: Caller said "Speak to miss Emma" but agent asked for caller's first name. Step 1 didn't explicitly cover "specific person by name → Path 4."

4. **Identity before intent** — SCL_MCFTYbDdZmXh, turn 4
   Root cause: Agent asked for name before understanding the caller needed a referral (transfer-worthy). Step 1 wording was too vague.

5. **Subscriber name inferred from email** — SCL_SuQdqrt9Ys9g, turn ~105
   Root cause: Agent inferred subscriber name from email address instead of asking. Tool description allowed it.

## Changes Made
1. RUNBOOK.md: Added Spanish compound phone number guidance under General Rules
   Why: Prevents multi-turn confusion loops when Spanish speakers use diez/once/doce for digits

2. RUNBOOK.md: Added day-of-week verification rule under General Rules
   Why: Prevents booking on wrong day when caller asks for specific weekday

   Why: Prevents fabricated or guessed subscriber names
