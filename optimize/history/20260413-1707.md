## Issues Found

1. **Mid-stream echo of collected fields** — SCL_sqzfRD9iU4xJ T9, SCL_5tJgWjUa436C T10/T11, SCL_xstNMuRQFqVG T29, SCL_wm4GD27oitnH T13, SCL_DCSmrdc9gdnU T19-T21
   Agent echoed name, phone, email, or partial values between collection fields. Sometimes fabricated invented pieces (Camille) that the caller hadn't said.
   Root cause: VOICE.md "Acknowledgments" said "just move to the next question" and "rotate 'ok' 'perfect' 'alright' or just move on silently" — ambiguous about whether the acknowledgment could include the value the caller just gave. Pacing rule about staying quiet only covered DURING dictation, not between fields.

2. **Excessive get_availability on adjacent dates when API already returned a forward-looking slot** — SCL_Cta8p6vxVZh2 (8 tool calls in 9 turns)
   Backend's response already tells you the next available date within 14 days via the `date` field. Agent kept querying 4-14, 4-15, 4-16, 4-17, 4-18, all returning the same 4-21 slot, one identical duplicate for 4-14, another identical duplicate for 4-17.
   Root cause: RUNBOOK's general rule "Use tool results you already have" is abstract; the tool description said "Scan existing results before calling again" but didn't tell the agent that `date != searchedDate` IS the definitive answer.

3. **Agent re-engaging after caller signals they're done** — SCL_nu6wr8TtYVoJ T7-T10
   Caller said "I'll catch you later. Thank you very much." Agent then launched into AI disclosure, "anything else you need?", "yeah, what's up?", "what can I help you with?" — four extra turns.
   Root cause: Path exits say "pause and let them lead" but nothing covers "they already said thanks/bye — close out."

## Changes Made

1. `workspace/VOICE.md` Acknowledgments — rewrote to include two concrete negative examples of the observed failure modes, plus explicit "only read-back is the single confirmation at the end of registration."
   Why: The LLM was interpreting "acknowledge" as license to restate the value. Concrete negative examples that mirror the actual transcripts make the boundary unambiguous.

2. `src/tools.ts` get_availability description — added explicit rule: if returned `date` differs from `searchedDate`, the API already scanned forward 14 days and that IS the nearest opening — offer it and stop searching. Don't re-query dates in between.
   Why: In SCL_Cta8p6vxVZh2, every query between 4-14 and 4-18 returned the same 4-21 answer; the agent kept querying because the existing "scan existing results" wording didn't explain WHY further queries would be redundant.

3. `workspace/RUNBOOK.md` General Rules — added: "Close out when the caller is done. If they say 'thanks,' 'bye,' 'have a good one,' or otherwise signal they're finished, respond briefly ('you're welcome, take care') and stop. Don't ask 'anything else?' after they've already wrapped up."
   Why: SCL_nu6wr8TtYVoJ had four unnecessary re-engagement turns after the caller signed off.
